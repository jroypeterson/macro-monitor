# macro_monitor — Project Instructions

See `README.md` for the full project description, workflows, and secrets table.

- **The pinned channel overview states facts about config — DERIVE them, never write them as prose.** `publishers/overview.py` computes the Tier A/B series counts, the Tier B gate threshold, the z-score lookback, and the delta-vs-level split from `release_families.yaml` at render time. The header used to read a hand-written `|z| ≥ 1σ vs trailing 5y` — true when written, and a lie the moment a family ships with a different gate. Anything non-uniform is named explicitly rather than averaged away (today: 13 of 14 Tier B families gate on the *move*, but Loan Delinquency Rates gates on the *level* — deliberately). `FamilyConfig.context` and `.tier_b_gate` are both `Optional`, so guard every read: a family missing either must degrade the note, not raise and take the whole pin down. Tests in `tests/test_overview_dashboard_links.py` are the pin.

- **Posting the overview does NOT pin it.** `cli overview --post` publishes a new message and prints "now go pin it manually" — the ClaudeBot app has `chat:write` but **not** `pins:read`/`pins:write`, so no code path can pin, unpin, or even list pins. Each repost therefore leaves another copy in-channel and the *previous* pin stays up until a human unpins it (as of 2026-07-30 two stale June overviews were still pinned). Adding those two scopes + reinstalling the app would let the command pin itself and retire superseded copies.

- **Global-macro / OECD BCI gotchas** — see `README.md` § "International 'Global macro' layer". The load-bearing one: FRED's OECD mirrors (`BSCICP03USM665S` et al) are **discontinued but still return HTTP 200 + well-formed CSV** ending 2024-01. Always go direct to OECD SDMX.

- **[ClaudeFin] email alerts** (root `CONVENTIONS.md` §5 "Email alerts"): the weekly Ahead-of-the-Curve rebuild lane (`ahead_of_curve.yml`, Mon 11:00 UTC → `cli ahead-of-curve --email`) emails a short pointer alert via the self-contained `email_alert_client.py` (vendored, not the `_shared/` shim, because this lane runs in CI). Subject grammar `[ClaudeFin] macro_monitor — <what>` (pass only the `<what>` part); **non-gating** — a failed send is a stderr `[WARN]` + Actions `::warning::`, never a failed run; **weekly-lane-only** — do NOT add email alerts to daily lanes (releases, fed-speeches, research digest).

- **🧱 Block Kit ceiling guard on the digest schedulers (2026-08-04, board #268).** `publishers/slack.py` has validated + chunked its release digests since #264; `schedulers/fed_speeches.py` and `schedulers/research_digest.py` never picked it up and handed their whole block list to `chat_postMessage`. Both build blocks in a **loop over new items**, so the count scales with how eventful the day was — the failure correlates with the value of the message, and Slack answers >50 blocks with `invalid_blocks`, which names nothing. `publishers/guarded_post.py` validates, names any violation on stderr *before* Slack is asked, and **splits into threaded continuations — never truncates**, because a shorter digest silently drops speeches. **VENDORED, not shimmed:** it imports the local `slack_blocks_client`, not `_shared/` — these lanes run in GitHub Actions with `PYTHONPATH: /tmp/pkg` where the Dropbox sibling is not checked out, so a shim would import fine on the laptop and go silently inert in CI. ⚠ **A lost continuation returns `ok=False` on purpose.** Both callers do `if ok: record_posted(payload)`, which permanently dedupes every URL in the payload — including the chunk Slack never received, which no future run would then re-send. Codex caught this; my first version returned True reasoning "the reader has the digest", and my test asserted that wrong behaviour. The trade is duplicates vs. permanent loss, and the fleet already made this call in these words on the fr-feed path: *"do NOT record so a retry re-alerts (no silent loss)"*. Verified end-to-end: a 118-block digest splits 50 + 50 + 18 with every block preserved.

- **🔒 EVERY workflow that writes `state/posts.db` must queue in `macro-posts` AND refresh before posting (2026-09-21, board #405/#420).** Three lanes write that binary SQLite ledger — `release_polling`, `reconciliation` and now `fomc_statement` — and both halves are load-bearing. **Serialising alone is not enough:** a concurrency group orders EXECUTION, not the checkout, so a run that sat pending starts from the `github.sha` it was queued with, reads a ledger from before the previous run's push, concludes the period is unposted, **posts a duplicate**, and only then loses its own row to the binary rebase. Hence `git fetch --depth=1 origin <default> && git reset --hard FETCH_HEAD` immediately before the posting step in all three. ⚠ **FOMC left this group once already**, on a review whose stated premise — "fomc_statement.yml commits no state" — was made false by a later commit on the same branch that gave it a ledger write; the comment claiming the group "serialises ... so they never race" survived and was serialising FOMC only against itself. The argument for the current arrangement, and the prerequisite for ever reversing it (make the ledger write survive a concurrent push — merge the row, don't rebase the file), is in the concurrency comment in `fomc_statement.yml`. The test is DERIVED — every file containing `git add state/posts.db` must be in the group and must refresh first — because the hand-maintained list of two workflow names is exactly what failed to notice when FOMC became a third writer.

- **A failed FOMC analysis is not a decision.** `analyze_statement` returns the `StatementVerdict` DEFAULTS on any failure — SDK missing, no API key, an API exception, a parse error — which reads as a perfectly plausible `HOLD · neutral · no target`. Only missing statement TEXT used to be guarded, so those were posted to `#macro-and-markets` as real Fed decisions and then RECORDED, permanently suppressing the retry. `analysed: bool = False` is now set True only by `_parse` on the success path, and `_parse` REJECTS a missing or invalid `action`/`stance`/`summary` rather than coercing them to the defaults. ⚑ `target_range` stays OPTIONAL on purpose: the genuine 2026-09-16 analysis rendered "target —" because the Fed did not restate the range in the form the prompt asks for, so requiring it would reject a real, correct read. ⛑ The gate tests originally did `monkeypatch.delenv("ANTHROPIC_API_KEY")`, which selected that very fallback — so 168 lines of "happy path" tests asserted the lane should post it. The harness now stubs `analyze_statement` through the real `_parse` and mirrors all three branches of its contract.
